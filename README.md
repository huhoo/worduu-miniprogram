# 字伴 · 微信小程序

儿童识字 App 的小程序版本，从 React Web 版（`字伴/ziban`）迁移而来。
核心闭环：**拍照识字 → 生字库 → 认读测试 → 笔顺书写 → 听写默写 → 识字档案 →
阅读伴读 → 成就分享**。

AI 能力跑在微信云开发上（云函数 + 云存储），不依赖自建服务器、不需要备案域名。

## 与 Web 版仓库的关系

独立仓库，**不与 Web 版共仓**。两套技术栈没有一行共享代码
（Web 版是 React 19 + Vite + Tailwind + Deno 后端，这里是原生 WXML/WXSS/JS + 云函数），
共仓只会带来 monorepo 的配置成本，换不来任何复用；微信开发者工具也要求
打开的根目录就是小程序目录。

两边靠**数据**而不是代码保持一致，同步点只有笔顺与笔画名，见
[`tools/`](#笔画名称从哪来为什么不问-ai)：

| Web 版改动 | 这里怎么跟 |
|---|---|
| `scripts/build-stroke-data.mjs` 输出的分片（`{ m: 中心线, n: 笔画名 }`） | 覆盖 `tools/strokes/`，需重新上传云存储 |
| cnchar 笔画表（`scripts/vendor/cnchar/stroke-order-{jian,trad}.json`） | 覆盖 `tools/vendor-cnchar/`，然后跑 `node tools/build-cnchar-strokes.mjs` 重新生成随包数据表 |
| 云函数里 `handleStrokeData` 的分片解析 | 这里同样兼容旧格式，只认 `entry.m` |

当前对齐的上游提交：`b3dc28a`（补繁体笔画名、`点2` 落地为「点」、双名不再取首项）。

## 一、跑起来需要做什么

### 1. 换成你自己的 AppID

打开 `project.config.json`，把 `appid` 从 `touristappid` 换成你在
[微信公众平台](https://mp.weixin.qq.com/) 注册的小程序 AppID。

> 游客模式（`touristappid`）**不能**使用云开发，AI 相关功能全部不可用。
> 只想在本地看看界面可以用游客模式，但要跑通拍照识字必须换成真实 AppID。

### 2. 开通云开发环境

1. 微信开发者工具 → 工具栏「云开发」→ 开通（个人主体可用，有免费额度）
2. 记下**环境 ID**（形如 `ziban-1g8xxxxxxx`）
3. 填入 `utils/config.js` 的 `cloudEnv`

```js
module.exports = {
  cloudEnv: 'ziban-1g8xxxxxxx',   // ← 改成你的
  cloudFunction: 'ziban',
  ...
};
```

### 3. 部署云函数并配置密钥

1. 在开发者工具左侧文件树找到 `cloudfunctions/ziban`
2. 右键 → **「上传并部署：云端安装依赖」**（会自动装 `wx-server-sdk`）
3. 云开发控制台 → 云函数 → `ziban` → **配置** → 环境变量，添加：

| 变量 | 必填 | 说明 |
|---|---|---|
| `DASHSCOPE_API_KEY` | ✅ | 阿里云百炼 API Key |
| `DASHSCOPE_WORKSPACE_ID` | ✅ | 百炼业务空间 ID（用来拼主机名） |
| `DASHSCOPE_REGION` | 选填 | 默认 `cn-beijing` |
| `QWEN_VISION_MODEL` | 选填 | 默认 `qwen3-vl-plus` |
| `QWEN_TEXT_MODEL` | 选填 | 默认 `qwen-plus` |
| `QWEN_TTS_MODEL` | 选填 | 默认 `cosyvoice-v3-flash` |
| `STROKE_FILE_PREFIX` | 选填 | 笔顺数据 fileID 前缀，见下一节 |

> ⚠️ Key 只存在云函数环境变量里，**绝不写进小程序前端代码** —— 小程序包可被反编译。

### 4. 创建成就卡数据库集合（要分享奖状就必做）

成就分享把卡片存在云数据库里，分享链接只带一个十来位的 id。

1. 云开发控制台 → 数据库 → 新建集合 **`achievement_cards`**
2. 权限建议保持默认（云函数走服务端权限，不受客户端权限限制）

没建集合时，点分享会提示「奖状没能保存，请确认云开发数据库里已创建 achievement_cards 集合」，
其余功能不受影响。

> 集合会随每次分享增长。如果担心，可以在控制台定期清理，或给云函数加定时触发器清理旧卡片。

### 5. 上传笔顺数据（可选，但不做就没有笔顺动画）

笔顺数据来自 Make Me a Hanzi（ARPHIC 许可），共 99 个分片、6.9MB。
塞进小程序主包会超过 2MB 限制，所以走云存储按需拉取。

分片格式是 `{ "字": { "m": 中心线, "n": 笔画名 } }`；云函数同时也认旧格式
（`{ "字": 中心线数组 }`），所以旧数据传上去不会坏，只是没有笔画名。

1. 云开发控制台 → 云存储 → 新建文件夹 `strokes`
2. 把 `tools/strokes/` 下的 99 个 `.json` 全部上传进去
3. 点开任意一个文件，复制它的 **File ID**，形如：
   `cloud://ziban-1g8xxx.636c-ziban-1g8xxx-1301234567/strokes/2e.json`
4. 取到 `strokes/` 之前的部分，填成环境变量：
   ```
   STROKE_FILE_PREFIX = cloud://ziban-1g8xxx.636c-ziban-1g8xxx-1301234567/strokes
   ```

没配的话，字详情页和书写页会显示「这个字暂无权威笔顺数据，因此不提供逐笔演示」——
这是**刻意**的降级：宁可不演示，也不拿模型猜的笔顺教孩子写字。

### 6. 用微信开发者工具打开

开发者工具 → 导入项目 → 选择本目录 → 填入 AppID → 打开。
点击编译即可预览；真机预览点「预览」扫码。

## 三、和 Web 版的差异（重要）

| 能力 | Web 版 | 小程序版 | 原因 |
|---|---|---|---|
| 拍照识字 OCR | ✅ qwen3-vl-plus | ✅ 相同 | 走云函数，Key 不落前端 |
| 查字、书写批改 | ✅ | ✅ 相同 | 同上 |
| 语音合成发音 | ✅ CosyVoice | ✅ 相同 | 音频落临时文件后播放 |
| 笔顺动画 | SVG path | **canvas 绘制** | 小程序不支持 SVG |
| 笔画名称（横/竖/撇/捺） | ✅ | ✅ 相同，且支持本地查表 | 数据表随包发布，见下节 |
| 认读评测 | 浏览器 ASR + AI | **家长旁听点选** | 小程序无内置语音识别 |
| 听写默写 | ✅ | ✅ 相同（笔画数作兜底判定） | 走同一个 evaluate-writing 接口 |
| 识字档案 | ✅ | ✅ 相同（熟练率环改用 canvas） | 数字全部由字库推导 |
| 阅读伴读 / 书架 | ✅ | ✅ 相同（三种朗读模式、点字查义） | 整句朗读复用 tts-speech |
| 成就分享（海报 / 点赞） | ✅ | ✅ 相同（海报改用 canvas 现画） | 小程序无 DOM，不能截 DOM 生成图 |
| 分享链接 | URL 参数带整张卡 | **云数据库 + 短 id** | 见下节，链接不会被聊天软件截断 |
| 伴读时长 | 页面可见时长 | **app 前后台打点** | 切后台不计时，单次上限 30 分钟 |

### 为什么认读测试改成家长判断

Web 版靠浏览器的 `webkitSpeechRecognition` 拿到孩子读了什么，再交给模型判断。
小程序没有等价能力（微信同声传译插件需要单独申请，且只支持有限场景）。

所以这里改成**家长旁听后点选「读对了 / 没读准」**，页面上也如实写明
「记录的是真实判断，不是机器猜测的分数」。
掌握度更新、反应时间、错字本这些逻辑和 Web 版完全一致。

如果之后接入了语音识别，只需替换 `pages/quiz/quiz.js` 的 `answer()` 里
`correct` 的来源即可，其余不用动。

### 为什么笔顺数据放云存储

6.3MB 超过小程序 2MB 主包上限。放分包技术上可行，但会让分包加载时一次性
占掉 6.3MB 内存；放云存储按需按字拉取，只取当前这一个字所在的分片（约 64KB）。

### 听写默写怎么判分

**出卷**：一次 5 个字，优先没默写过关的，再补错过的字，最后才是其余。三档之间去重，
不会出现同一个字被抽两次。

**判定**：提交后把田字格整幅导出成 PNG 送云函数，复用和规范写字同一个
`evaluate-writing` 接口（同一个 prompt、同一套「不要因为鼓励而虚高」的要求）。

**AI 不可用时的兜底**：拿不到书写图像、或云函数报错时，只按「笔画数差 1 以内」判定，
并在结果卡上写明「本次仅核对了笔画数 / 仅按笔画数判定，请家长复核」——
**不编造字形分数**。

**写回字库**：默写过关记 `canDictate`，掌握度升为「熟练」，备注「已经能够认读、书写、默写」；
不过关保持「经常读错」并累加错误次数。分桶计数（熟练/基本/不熟/错字）始终由字库推导，
不做并行累加，避免数字漂移。

### 笔画名称从哪来，为什么不问 AI

笔顺动画现在会显示每一笔的标准名称（横 / 竖 / 撇 / 捺 / 横折钩 …），并支持「第 N 笔：横」逐步播报。

数据来自 **cnchar 的笔画表（MIT 许可）**，原始文件存档在 `tools/vendor-cnchar/`
（含 LICENSE 与 NOTICE.txt）。为了不占主包体积，只保留「字 → 笔画字母串」和
「字母 → 标准名」两份映射，压成 `utils/data/cnchar-strokes.js`（9,504 字，234KB，
由 `tools/build-cnchar-strokes.mjs` 生成），随包发布，
因此**即使不上传云存储分片，笔画名也能显示**（只要该字有笔顺动画）。

cnchar 的简体表（6,939 字）和繁体表（2,611 字）近乎不相交 —— 只共有 46 个字，
且这 46 个字两表一致。所以两张表都查，简体优先、繁体兜底，繁体字也有笔画名。

为什么不问大模型或靠几何推断 —— 上游实测过两条路都不可靠：

- 模型：3 个抽样字里 2 个顺序错；「雨」在 temperature 0 下两次调用笔画数还不一样（8 vs 10）。
- 几何分类器：用中心线方向判断，15 个已知答案的字只对了 1 个 —— 曲率会被当成方向变化，
  「十」这种两笔的字会被判出三个名字。

所以采用**两个独立数据源交叉校验**：只有 cnchar 的笔画数与 hanzi-writer 的中心线笔数
一致时才标注名称。实测 9,574 个有笔顺数据的字里，8,610 个（89.9%）能标注；
剩下 964 个 —— 166 个两源笔数冲突、798 个 cnchar 两表均未收录 —— 保留动画、不标名称，
页面上也写明原因，不猜。

笔数相同还不等于顺序相同，而 UI 是逐笔标注的，等于在断言顺序，所以顺序也核对过：
首笔为基本笔画的 5,921 个字里，cnchar 的名字能预测 hanzi-writer 实际绘制方向的
占 99.6%~100%（横 1977/1978，竖 1089/1093，撇和点 100%）。两源是对齐的，不只是等长。

另外两处不替数据源做它自己没做的决定：cnchar 有 5 个笔画给了两个并存的规范名
（如「斜钩|卧钩」），两个都显示用 `/` 连接 —— 只取第一个会让「心」的第二笔读成斜钩，
而它其实是卧钩；字母 `d` 在 cnchar 里叫「点2」，那是表内消歧标记不是笔画名，
按其几何归属（向下的点）落地为「点」。

### 成就卡分享：为什么改成「存库 + 短 id」

Web 版把整张卡片 base64 编码进分享链接，代价是链接很长，微信等聊天软件一截断，
接收方就只能看到「这条分享链接打不开」。

小程序有云开发，所以改成：分享前把卡片写进云数据库 `achievement_cards`，
分享 path 只带一个十来位的 id（`/pages/share/share?id=xxx`）。
接收方打开后按 id 取卡 —— 链接再短也不会被截断。

- 入库前云函数做一次 `sanitizeCard`：昵称截断 12 字、标题 40 字、生字最多 4 个、
  时长与总量非数字一律归 0、未知 type 落为 `daily`。卡片数据来自客户端，
  不能直接落库再原样渲染。
- 点赞走同一个云函数写回，所有亲友都能看到；本机另外留一份标记，
  用来判断这台设备是否已经点过，避免重复刷赞。
- 云写失败时点赞仍在本机可见，并如实提示「没能同步到云端」—— 亲友的心意不该因为网络丢了。

### 伴读时长是怎么算的

计时在 `app.js` 用 `onShow` / `onHide` 打点，只累计**前台**时间：

- 切到后台就停，挂机不会刷出时长
- 单次结算上限 30 分钟 —— 孩子把小程序挂在后台一晚上，不该凭空多出几小时
- 每天零点随字库一起归零

首页、「今日伴读」和成就卡上的「专注学习 X 分钟」都读同一个数字，
没有预设值：没用过就是 0 分钟。

### 内置示例读物

`utils/data/articles.js` 里的 4 篇文章是**示例读物**，不是孩子自己读过的书，
书架页顶部也如实标注了。每本书的「已收录 / 已掌握」全部由你自己的字库实时推导，
不写在文章数据里 —— 否则换一个孩子打开，会看到别人的进度。

迁移时改了一处原文错字：《春天的森林》第三句原为「蝴蝶**统**一下飞走了」，
应为「蝴蝶一下子飞走了」。这是给孩子朗读的课文，错字比没书更糟。

封面原版用的是 unsplash 外链图片，小程序里要显示得先在后台配 downloadFile 合法域名，
否则一片空白。这里改成 emoji 封面，零配置、零流量。

一个已知的数据瑕疵（沿用上游记录）：cnchar 对「捺→点」的构件变体处理不一致，
所以「森」会显示 横竖撇捺 / 横竖撇点 / 横竖撇捺 —— 顺序和笔画数是对的，只有每个「木」的
第三笔名字不同。

## 四、常见问题

**Q：所有 AI 功能都提示「尚未配置」**
检查三件事：AppID 不是 `touristappid`、`utils/config.js` 的 `cloudEnv` 填了、
云函数的环境变量 `DASHSCOPE_API_KEY` / `DASHSCOPE_WORKSPACE_ID` 都填了且已重新部署。

**Q：拍照后一直在转圈**
打开开发者工具的「云开发 → 云函数 → 日志」，看是否有上游报错。
最常见的是 `DASHSCOPE_WORKSPACE_ID` 填错 —— 百炼会返回
`Workspace endpoint is invalid`，这种情况把环境变量 `DASHSCOPE_BASE_URL`
直接写成 `https://dashscope.aliyuncs.com/compatible-mode/v1` 即可绕开。

**Q：发音没声音**
确认手机没静音。云函数里 `QWEN_TTS_MODEL` 与音色 ID 必须配套 ——
`longxiaochun_v3` / `longcheng_v3` 只在 `cosyvoice-v3-flash` 下有效，
换成别的模型会返回上游错误（418）。

**Q：笔顺动画一直显示「暂无数据」**
`STROKE_FILE_PREFIX` 没配，或者填的 fileID 前缀和实际不一致。
在云开发控制台复制一个真实 File ID 核对。

## 五、数据来源与许可

**笔顺几何**来自 [hanzi-writer-data / Make Me a Hanzi](https://github.com/skishore/makemeahanzi)，
采用 ARPHIC PUBLIC LICENSE。详见 `tools/strokes/ATTRIBUTION.txt`，
许可要求的完整许可证文本 `ARPHICPL.TXT` 也一并存档在 `tools/strokes/`。

**笔画名称**（横/竖/撇/捺…）来自 [cnchar](https://github.com/theajack/cnchar) 的笔画表，
采用 MIT 许可。原始文件（含 LICENSE 与 NOTICE.txt）存档在 `tools/vendor-cnchar/`，
随包发布的是精简后的 `utils/data/cnchar-strokes.js`，文件头已注明来源与许可。

两个数据源是**独立交叉校验**的：只有笔画数一致时才标注名称，冲突则不标 ——
在教写字的 app 里，错的笔画名比没有更糟。
